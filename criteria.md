# Acceptance criteria - reference implementation

These are AI-drafted demonstration targets, recorded after the initial code
was implemented and before its live calibration. They are not independently
chosen, pre-build student criteria. Students must write and defend their own.
The calibration passages are all AI-authored; they cannot measure a human
false-positive rate.

## 1. Score spread

In each of three trials, the combined score of the regular, repetitive
calibration passage must exceed that of the irregular narrative passage by
at least 0.30.

**Why this target:** Two deliberately different surface patterns should not
collapse to the same score. This tests sensitivity, not authorship accuracy;
both passages were generated by AI.

## 2. Label coverage

Each of three trials over the four calibration passages must produce all
three guesses: `human`, `unsure`, and `ai`. Every successful response must
include numeric model, style, combined, and confidence scores in [0, 1].

**Why this target:** A three-label interface is misleading if one label is
unreachable through a real submission. Exposing both signals also makes
disagreement diagnosable.

## 3. Appeal traceability

For each of three new submissions, an appeal with its returned `content_id`
and nonblank reasoning must return HTTP 200 and `status: under_review`.
The audit history must preserve the original `decided` entry unchanged and
append an appeal with matching content and creator IDs and the supplied
reasoning. An unknown ID must return 404 without recording an appeal.

**Why this target:** A person challenging a decision needs a recorded review
request, not a silently edited decision or a false promise of reassessment.

## 4. Invalid input

Across three trials, missing, empty, whitespace-only, null, and non-string
text, missing creator ID, non-object JSON, and malformed JSON must return
400; non-JSON content must return 415; fewer than three words must return
422. None may create a decision, and each must create a rejection entry.

**Why this target:** Bad requests must not reach expensive model inference
or appear to have been successfully classified. Their rejection must remain
visible in the audit trail.

## 5. Size limits

Across three trials, text longer than 10,000 characters and request bodies
larger than 65,536 bytes must return 413 with a JSON error and a rejection
entry. Reasoning longer than 2,000 characters must return 400 without an
appeal entry.

**Why this target:** Explicit bounds make the endpoint contract predictable
and limit work before inference. A size limit does not solve model latency
or protect against many separate requests.
